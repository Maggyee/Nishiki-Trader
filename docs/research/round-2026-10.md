## How a stage runs

`python -m apps.research.protocol run <contract> --stage development|confirmation`

- Data: Binance Vision only, SHA256-checked against the published
  `.CHECKSUM`, cached under `data/research/`. Dates from 2026-09-01 are refused
  (sealed blind).
- Replay: weights decided at a daily close apply to the next day's return.
  Constant notional (10,000 USDT, two-sided, gross ≤ 1). Costs per fill on
  traded notional: base 12 bps, stress 15 bps.
- Null: each asset's position series is circularly shifted against its returns
  (5,000 trials). This keeps exposure, turnover, holding cadence and long/short
  mix, and destroys only timing.
- Gates: base and stress > 0; positive years ≥ 2/3 of window years; positive
  months > null median (§11); ≥ 60 closed positions; leave-best > 0;
  base > benchmark (mean net weight × constant-notional buy-and-hold per
  asset); null p ≤ 0.10.
- Confirmation runs only for identities that passed development.
- Interpretation fixed before any PnL: the contracts write 2/3 as 0.6667, read
  with a 0.001 tolerance (2 of 3 years passes; 2 of 2 needed for 2-year windows).
- v55 amendment before any PnL: USD-M archives start 2020-01, so the fetch
  start moved from 2019-09; rules, windows and gates unchanged.
- Results go to `docs/research/results/`; the registry is updated in the same
  commit.

## Stop rule

If no identity passes confirmation, the round ends with a written conclusion
and the operator decides what next. A pass goes to a Nautilus backtest and a
local paper session for learning; it is not a promotion.
