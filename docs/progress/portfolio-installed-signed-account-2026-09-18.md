# Installed signed fixture account exchange

Date: 2026-09-18. Phase: disposable local integration only. This joins the
[isolated native request signer](portfolio-installed-native-requests-2026-09-17.md)
to the existing root HTTPS transport and native response consumer. Exact source,
artifact and verification pins are in the matching JSON.

## Result and scope

One signed `GET /api/v3/account` now completes the installed fixture boundary:

1. The root controller issues a fresh challenge to the exact isolated PID/UID/GID.
2. The dedicated UID uses Nautilus 1.226.0 Ed25519 signing with the public RFC 8032
   test key. Root verifies the exact selector, signature and original clock bounds.
3. Root persists and holds `account-request.json`, then prepares a separate
   account ledger entry binding the request hash before granting the expiring mark.
4. The root-owned socket verifies local TLS and sends the exact signed query and
   fixture key header. The independent local HTTPS peer verifies the signature
   and exact request encoding too. Raw response bytes and receive clocks are saved.
5. Root revokes kernel permission before transferring the original response to
   the child. The child constructs native Currency, Money and AccountBalance
   objects and checks exact amounts before its final authenticated receipt.
6. Only the matching native balance receipt permits a successful ledger outcome.
   A failure or missing receipt keeps the prepared attempt consumed and pending.

The fixed response retains BNB, BTC, ETH and USDT, including ETH's zero balance,
BTC/BNB locked amounts and USDT free/locked cash. Precision is selected as eight
places for this fixture. These are four synthetic assets, not the actual 502-asset
account, same-run metadata or qualified equity. The selected UID is synthetic 41001.
There is no account stream fence, repeated REST collection, route derivation or WS
integration in this profile. The complete 20-operation native joint collector is
still separate. Its 16 GET / 448-weight local budget and the frozen real 17 GET /
468-weight draft remain unchanged. This is one local GET / 20 documented weight.
The request's challenge index 3 selects the fixed account-read template; the new
single-attempt ledger index is zero and does not imply earlier joint steps ran.

The test key is public and supplies no real credential/source authority. No operator
credentials, real venue requests, consumed approval scopes, host installation,
firewall maintenance window, service or live execution path were used or changed.

## Implementation and failure boundaries

`gateway_native_account.py` owns the exact account selector, immutable request
selection, fixture rates/body mapping, native balance consumer and explicit reader
views. Supplemental fixture manifest v7 pins thirteen project-owned sources.
The unchanged base launcher and frozen child runtime keep native imports outside
root. Runtime initial hashes, held descriptors, metadata/mount checks and their
prior root-race/OS-library/rollback limitations remain as documented in the
[native metadata acceptance](portfolio-installed-native-receipt-2026-09-17.md).

The separate `portfolio.fixture_signed_account_tls_ledger.v1` profile and
`fixture-signed-account-tls-v1` scope accept only one collector account-read attempt.
Preparation and outcome carry the same original request hash. Alternate operations,
a second attempt or a changed outcome hash are refused. The request original is
root-owned mode 0600, fsynced with its directory, then held by installation authority.
The TLS journal additionally binds its exact selection hash, ledger prefix, kernel
prefix, local endpoint, peer and original request bytes. Earlier ledger/TLS/receipt
profiles retain their original semantics; signed-account replay needs the explicit
selected contract and account reader, never an inferred downgrade.

The five-second signature window is rechecked before connect and immediately before
request write. Signature verification and binding checks consume that same window:
a second time sample after verification limits the remaining socket timeout, also
bounded by the existing TLS deadline. Neither validation delay nor a completed TLS
handshake can renew an expired signature. This validates local fixture clock use;
actual provider clock qualification remains absent.

Account responses do not advertise exchangeInfo `rateLimits`. The account reader
preserves the original `X-MBX-USED-WEIGHT-1M` counter and refuses duplicate/ambiguous
headers; limits, RAW_REQUESTS usage and connection charge remain unknown. The
counter's original header/body receipt clocks are not regenerated by delivery or
replay. No inferred remaining quota or real dispatch admission results.

Nautilus Money can round excess decimal precision. The consumer compares every
native total, locked and free amount to the original Decimal value, then checks the
AccountBalance round trip. A response containing 0.000000001 BTC completes TLS but
fails `native_account_rounding_refused`, preserving its original bytes, missing
receipt and pending attempt. Duplicate/missing/unknown assets, wrong UID, negative,
nonfinite and non-string amounts are rejected. Successful acknowledgement means
exact fixture object construction, not execution or account-source qualification.

Detached replay revalidates the native signature, original selected request,
received-before-prepared order, exact encoded TLS request, original signing window,
raw response, kernel revocation and final native receipt/outcome ordering. It cannot
refresh request timestamps, infer current kernel state or repair a missing receipt.
A separately reconstructed native balance is not proof the original child acknowledged it.

## Verification and evidence

- **29 new / 762 focused tests pass**, no warnings, in 77.82 seconds. Tests cover
  signature-to-wire binding, exact native balances/zero assets, precision refusal,
  expiry before connect/write and during verification, fixed single-attempt schema,
  selected-contract/profile requirements, rehashed request/receipt/clock tampering,
  and the existing native request, TLS, receipt, ledger and installation regressions.
- **49 actual current-source disposable scenarios pass**: seven signed account,
  seven native metadata, seven native request, eleven stdlib receipt, six TLS,
  six IPC and five echo. Each retains the base 40-check installation acceptance.
  Account scenarios cover success, slow body, native precision loss, runtime remount
  drift, bad certificate, stopped consumer timeout/kill/reap and controller SIGKILL.
- The final account scenarios have 65, 65, 65, 67, 63, 68 and 67 checks. Independent
  local peer reports bind the actual query hash and signature verification for all
  cases that send an HTTP request. The bad certificate case sends no HTTP request.
- Two fresh system-Python replays reproduce all 49 selected report sets exactly,
  with socket creation and DNS disabled. Two frozen-runtime native replays reproduce
  21 scenario sets: 87 original signed/unsigned request envelopes (80 prior-profile
  requests plus seven account requests), native balances and metadata objects,
  including both precision refusals and original missing acknowledgements.
- Ruff/format, diff, documentation links and exact source/artifact pins pass. Host
  account/install observations remain unchanged. Upstream source is untouched.

A concurrent account acceptance run timed out waiting for the native child to
become ready. The controller failed before account-ledger creation or network
activation. The base launcher and all production deadlines stayed unchanged;
the separate final account run passed all seven scenarios. This is fail-closed
behavior under the observed startup delay, not availability qualification under
concurrent load. The failed report and diagnostic remain unselected. The earlier
successful diagnostic run predates the final verifier-time check and is also
unselected. Earlier evidence directories remain immutable.

Selected originals are under `data/installed-signed-account-2026-09-18/`: seven
final reports, exact source copies, request selection/attempt/kernel/TLS/receipt
archives, `selection.json`, frozen public runtime bundles, drivers and two outputs
per replay. Local data/runtime binaries are ignored; the tracked JSON records pins.
